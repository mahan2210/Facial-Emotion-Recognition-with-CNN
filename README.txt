==========================================================================
Facial Expression Recognition on FER-2013

==========================================================================

This README explains how to download the datasets and run the code to
replicate every result in the final report.

--------------------------------------------------------------------------
1. CONTENTS OF THE CODE PACKAGE
--------------------------------------------------------------------------
Final_Submission_Notebook.ipynb   THE single submitted notebook. Contains all
                                  five project phases IN ORDER with the
                                  executed results (tables and figures)
                                  embedded: Phase 1 data pipeline, Phase 2
                                  seven-architecture comparison, Phase 3
                                  Optuna tuning + ablations, Phase 4 test
                                  evaluation + FGSM robustness, Phase 5
                                  adversarial-training defence + demo export.
                                  Its first code cell (%%writefile) creates
                                  fer_lib.py automatically, so no separate
                                  library file is needed.
webcam_demo.py                    Real-time webcam demo (also regenerated by
                                  the Phase 5 cells of the notebook)
artifacts/                        Created at runtime: checkpoints, JSON
                                  results, figures, manifest.json

--------------------------------------------------------------------------
2. ENVIRONMENT SETUP
--------------------------------------------------------------------------
Python 3.10 or newer. A CUDA GPU is strongly recommended (experiments were
run on a single CUDA GPU); CPU works but is slow.

    pip install torch torchvision numpy pandas scikit-learn matplotlib
    pip install seaborn optuna opencv-python jupyter

--------------------------------------------------------------------------
3. DATASET DOWNLOAD
--------------------------------------------------------------------------
Create a folder named  data/  next to the notebooks and place two files in it:

(a) FER-2013  ->  data/fer2013.csv
    Download from Kaggle:
    https://www.kaggle.com/datasets/deadskull7/fer2013   (fer2013.csv), or
    https://www.kaggle.com/datasets/msambare/fer2013     (image folders;
    the notebooks expect the CSV version with columns emotion,pixels,Usage)

(b) FERPlus  ->  data/fer2013new.csv
    Download from the Microsoft FERPlus repository:
    https://github.com/microsoft/FERPlus  (file: fer2013new.csv)
    Optional: only needed for the FERPlus label-noise analysis.

--------------------------------------------------------------------------
4. HOW TO RUN (REPLICATING THE REPORT)
--------------------------------------------------------------------------
Open Final_Submission_Notebook.ipynb and run it TOP TO BOTTOM. The notebook
already contains the executed outputs used in the report, so it can also be
read without running anything. Re-running proceeds phase by phase inside the
one notebook: each phase saves its outputs to artifacts/ and later phases
load them from there (manifest.json); if a prerequisite is missing, a clear
error names the cell section to run first. All runs are seeded (seed 42).

    jupyter notebook Final_Submission_Notebook.ipynb

Approximate wall-clock on one CUDA GPU, top to bottom: Phase 1 ~2 min,
Phase 2 several hours (trains 7 models), Phase 3 several hours (25 Optuna
trials + ablations), Phase 4 ~15 min, Phase 5 ~30 min (adversarial training).

Quick dry run: reduce the constants at the top of the expensive cells
(EPOCHS, REF_EPOCHS, TRIALS, TUNE_EPOCHS, ABLATE_EPOCHS, FULL_EPOCHS).

Resuming after a disconnect: restore fer_lib.py, the artifacts/ folder, and
data/, then continue from any phase. Nothing else is needed.

Webcam demo (after Phase 5 has run):
    python webcam_demo.py          (press q to quit; runs fully on-device)

--------------------------------------------------------------------------
5. MAPPING RESULTS IN THE REPORT TO ARTIFACTS
--------------------------------------------------------------------------
Table 1 (model comparison)      artifacts/phase2_summary.json
Table 2 (tuning)                artifacts/tuning_trials.csv, best_config.json
Table 3 (ablations)             artifacts/ablation_results.json
Tables 4-5, Figures 1-4         artifacts/phase4_results.json,
                                confusion_matrix.png, fgsm_curve.png,
                                fgsm_examples.png, adv_training_effect.png

Expected headline numbers (seed 42, single CUDA GPU):
  Fine-tuned ResNet-18 test accuracy   0.708  [95% CI 0.693, 0.722]
  Tuned (Optuna) variant               0.698  [95% CI 0.683, 0.713]
  Ablation: no augmentation            -3.1 points (validation)
  FGSM eps=0.01 accuracy               0.060
  After adversarial fine-tuning, eps=0.05:  0.216 (was 0.051)
Minor variation is possible across GPU models and library versions.

--------------------------------------------------------------------------
6. CODE ATTRIBUTION
--------------------------------------------------------------------------
All experiment code (data pipeline, FERPlus relabeling, training loop,
tuning/ablation harnesses, evaluation suite, FGSM implementation, notebooks,
webcam demo) is original work by Group 4. Model definitions adapt standard
torchvision constructors (resnet18, vgg16_bn, convnext_tiny) with
team-written stems and heads. Third-party dependencies: PyTorch,
torchvision, scikit-learn, pandas, matplotlib, seaborn, Optuna, OpenCV.
